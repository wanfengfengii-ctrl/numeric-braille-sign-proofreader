# 电梯厅数字房间牌 · 六点盲文校样台

纯前端校样台：把明眼稿房间牌代码编码为六点盲文目标单元带，与实物抄录单元逐点比较，避免“看似逐位对应、实际漏加数字标志”的错牌流出。

## 编码规则

- 点位编号：左列自上而下为 1、2、3，右列为 4、5、6。
- 数字标志固定为 `3456`；数字 1–0 依次为 `1、12、14、145、15、124、1245、125、24、245`。
- 连字符 `-` 为 `36`，斜杠 `/` 为 `34`，空格为空单元。
- 每个连续数字段前必须且只能出现一个数字标志；任一分隔符都会结束数字状态。
- 输入仅接受数字 0–9、半角连字符、斜杠和单个空格；分隔符不得位于首尾或连续出现。

## 校样流程

1. 左侧输入房间牌代码，实时得到目标单元带。
2. 右侧“添加单元”后逐点抄录：点击圆点，或聚焦单元后按 `1`–`6` 切换点位（`←`/`→` 移动、`Enter` 插入、`Backspace` 删除）。
3. 右侧实时反向解读出可解读代码；遇到缺少数字标志、数字标志重复、未知点阵，或代码结构非法（数字标志后未跟数字、分隔符位于首尾或连续出现）时不猜测字符，并清除旧的一致结果。
4. 比较以点集合为准：单元数量或任一点不同都判为不一致，并聚焦首个差异单元；全部一致时显示“房间牌一致 ✓ 可以送厂”。

## 点位串导入

供应商可从压点设备复制竖线分隔的点位串，校样员粘贴到实物抄录区的“点位串导入”输入框并点击“导入抄录”，无需逐格点按：

- 每格只接受升序且不重复的点位 `1`–`6`（如 `3456`、`12`），空白盲文格写作下划线 `_`。
- 竖线不得位于首尾，也不得形成空格段；整体首尾空白（如复制带出的换行）会被忽略。
- 示例：`3456|1|12|36|3456|14|34|3456|145|_|3456|15` 对应代码 `12-3/4 5`。
- 解析成功时一次性替换当前抄录格，可解读代码、首差定位与送厂结论随之刷新；之后仍可用键盘、指针、插入及删除操作修正。
- 若某格含越界点、乱序、重复点或缺失内容，界面指出第几个文本格及原因，并保留导入前的抄录与判定，避免半成品覆盖已核对数据。
- 解析结果沿用现有 Cell 位掩码、`decodeCells` 与 `compareCells`，手工抄录入口与编码规则保持兼容。

## 本地草稿

误刷新或隔日继续时，校样台把当前明眼稿、实物抄录单元与点位串输入自动保存为同一份本地草稿（localStorage），再次打开页面时提示恢复：

- 草稿随输入或抄录变化自动覆盖保存；全部清空时草稿一并清除，不打扰下次启动。
- 选择“恢复草稿”后一次性还原三项数据，目标单元带、反向解读、首差定位与送厂结论由 `validateCode`、`decodeCells` 与 `compareCells` 重新计算，草稿不持久化旧判定结果；恢复后点按、键盘、导入与清空操作照常可用。
- 选择“放弃草稿”则清除缓存，从空白工作区开始。
- 草稿为带模式标识与版本号的 JSON，由领域层（`src/draft.ts`）序列化并逐字段校验：内容无法解析、字段类型错误或单元值超出六点位掩码（0–63）时整体判为损坏，界面提示“草稿已损坏”并只允许放弃，空白工作区不被部分数据污染；此后正常编辑产生的新草稿仍会覆盖坏缓存。

## 技术栈

TypeScript + React + Vite；编码器由 Vitest 锁定全部映射与数字状态；Playwright 做端到端验收。

## 本地运行

```bash
npm ci
npm run dev        # http://localhost:3000
npm run test:unit  # Vitest
npm run test:e2e   # Playwright（自动拉起 dev server）
npm run verify     # 单元 + 端到端一次性验收
```

## Docker

```bash
WEB_PORT=8080 docker compose up web   # 宿主端口由 WEB_PORT 覆盖，默认 3000
docker compose run --rm verify        # 一次性验收服务：Vitest + Playwright，跑完即退出
```
